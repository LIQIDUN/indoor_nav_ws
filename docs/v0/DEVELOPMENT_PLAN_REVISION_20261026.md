## 3. 恢复后的执行顺序（待用户明确恢复）

### P1：准备悬停超时与普通 GPS 配置一致性

1. 对照最终单点 PASS 与四点准备 FAIL 的 telemetry、FC日志、起飞/高度基准及模式时间线。已知失败时真值约0.834m，未过驱动 Z>0.85m 且速度范数<0.06m/s 的35s门槛；深层原因尚未确认，不预判为纯驱动问题。
2. 核查起飞高度指令与 Gazebo/FC 高度参考是否一致、前次落地后的仿真状态是否残留；先用日志找原因，不为获得 PASS 随意延长超时或降低门槛。
3. 单点、四点分别使用全新隔离 runtime/EEPROM，待 Master、唯一 MAVROS、GPS/EKF 与参数回读就绪再运行；记录准备失败与航点执行失败的不同阶段。
4. 核对当前 `navigation.source=fc_ekf_fake_gps` 对 `/v0_nav/upstream_healthy` 的强制依赖。按普通 GPS/EKF 路径最小调整 schema、默认配置、健康逻辑和测试，使常规 GPS 运行不依赖缺失的自定义 adapter；如保留额外上游健康信号，应为明确配置的增强项。
5. 上述代码兼容调整**尚未实施**。不能用常量 `healthy=true`、伪造适配器或把真实飞机标为 SITL 来绕过当前门禁；GPS/EKF、pose/stamp/跳点、边界、速度和模式检查必须保留。

交付：最终版本独立冷启动单点及四点机器可读结果、参数与来源快照、目标/位姿/真值/速度/模式和日志路径；失败记录一并保留。

### P2：异常退出、掉线、模式切换的安全语义与测试

1. 验证人工切出 GUIDED 立即撤销任务所有权、取消后续点；即使切回 GUIDED 或连接恢复也不自动续飞、不自动抢模式。
2. 分开验证显式 abort、正常 stop、正常退出、崩溃/kill、心跳超时、MAVROS进程停止/遥测丢失；记录实际FC行为，而非只验证ROS状态或publish返回。
3. 明确取消后续点与取消飞控最后目标不是同一动作。评估可通信且定位健康时的可验证退出策略，以及定位不可信/通信断开/进程已死时只能依赖预设FC failsafe和飞手接管的边界。
4. 在方案经审查并于隔离 SITL 实测前，不新增未经验证的自动备用模式；不默认室内RTL，不以“当前点保持”掩盖定位失效，也不增加第二控制发布者。
5. 测试报告同时写软件锁存时间、停止输出时间、模式/目标变化及实际运动；不能以 ABORT_LATCHED 或停发成功作为已刹停结论。

交付：逐项故障测试与异常退出责任表；明确哪些动作已验证、哪些依赖飞控/RC、哪些仍不能保证。

### P3：唯一 MAVROS 与声学业务隔离

1. 检查同一次部署的 ROS Master、MAVROS、FCU串口占有者、位置/原始目标发布者唯一性；旧隔离环境的进程不能误算为当前部署，也不能误杀。
2. 真实采集代码可用时以机载最新版为准；只读核对配置，任何录包话题追加先经人工确认，不覆盖旧/新采集系统。
3. 在合成负载下先验证单业务/双业务、kill导航后采集/录包继续、kill音频不触发导航抢模式、MAVROS掉线时各业务反应；保存pose age、目标周期抖动、CPU、bag可读性和序号统计。
4. mock通过只证明通信隔离；真实XVF/IM72/ESC及ARM/DISARM自动录包列为R0及后续现场联合验证，缺硬件如实标注，不伪称已完成。
